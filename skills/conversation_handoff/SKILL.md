# 会话交接（总结 + 迁移）

## 适用场景

- 对话已经很长，每轮回传的上下文明显变大
- 一个任务已经闭环，要开始不相关的新任务
- 想保留结论，但不想继续背着历史往下走

## 自动巡检（可选，开局先查）

- 如果本机用 `workflow` 包搭了定时巡检（读实时对话列表的 `messageCount`，达标即写一个标记文件），**会话开局先读该标记文件**：存在 → 主动跑评估器并向用户提示是否交接；处理完**删除该文件**。
- 限制：这类巡检**只能判消息条数**。活跃窗口 `currentWindowSize` 没有任何工具能读到（实时接口与备份都没有），窗口阈值只能靠人工看 UI。

## 量化触发阈值

**先用评估器拿数据，不要凭感觉判断：**

```bash
python3 <Operit目录>/skills/conversation_handoff/scripts/context_gauge.py
python3 <Operit目录>/skills/conversation_handoff/scripts/context_gauge.py --chat <标题关键词>
```

| 信号 | 观察区间 | 建议交接 |
|---|---|---|
| 活跃窗口 `currentWindowSize` | 25K–45K | ≥45K 建议评估，≥75K 强烈建议（阈值可按需自定义） |
| 消息条数 | 100–200 | ≥200 |
| `<think>` 占正文比 | 18%–30% | ≥30%（实测单条 think 可超 10 万字符） |
| 工具类消息占比 | — | ≥30% 且任务已闭环 |
| 该对话缓存命中率 | ≥85% | <85% 说明前缀不稳定 |

**语义触发（需自行判断，优先级高于数值）：**

- 到达任务边界：一件事已闭环，剩下的是新目标
- 话题切换：新需求与旧上下文无关
- 反复解释同一背景超过 2 次
- 试错已收敛，只剩结论有用

## 执行步骤

1. 跑评估器，确认触发了哪几项
2. 起草交接文档（严格按模板），**必须先落盘再开新对话**
3. 落盘路径：`<Operit目录>/handoff/<主题>-<日期>.md`
4. 新对话首条消息 = 「背景 + 当前目标 + 指向交接文档的路径」
5. 旧对话保持不删（删对话不会删记忆库，见约束边界）

## 交接文档模板

按此结构写，不要自由发挥：

```markdown
# 交接：<主题>
日期 / 原对话标题：

## 1. 目标（当前仍在推进的）
## 2. 已确认的事实与结论（每条带依据）
## 3. 关键约束与决策（为什么这么定）
## 4. 产物与位置（路径 / 命令 / 配置项）
## 5. 未决问题与下一步（卡在哪）
## 6. 已排除的方案与原因（避免重走）
## 7. 关键标识符（ID / Key 名 / 版本号 / 阈值）
```

## 自过滤规则

**必须丢弃**（这些正是上下文膨胀的主因）：

- `<think>` 思考过程正文
- 原始工具输出（dump、日志、长列表、文件全文）
- 失败的尝试与被推翻的中间方案
- 客套、重复确认、已被总结过的内容

**必须保留**（丢一条就可能导致返工）：

- 最终决策 + 决策理由
- 约束边界与禁止项
- 确切路径、命令、配置键与取值
- 未完成的 TODO 及其阻塞点
- 用户明确表达的偏好与否定意见
- 已排除方案及其被否原因

## 无损校验清单

交接文档写完后逐条自检：

- [ ] 每个结论都能指向具体依据（文件 / 命令输出 / 用户原话）
- [ ] 文档里出现的每个路径都真实存在
- [ ] 未决问题都写明了「卡在哪」
- [ ] 不含任何「以后再补」的占位
- [ ] 全文不含 think 块和原始工具输出
- [ ] 剥离原对话后，单看本文档能继续推进任务

## 约束边界

- 交接前先落盘再开新对话，不要先关旧对话
- 交接文档只写结论与依据，不复述过程
- 不把交接文档内容写进 system prompt 或 Skill 正文（会破坏前缀缓存）
- 删除对话不会删除记忆库，不要依赖「删掉旧对话」来清理信息

## 期望输出

- 评估器结论（触发项 + 具体数值）
- 交接文档的落盘路径
- 新对话的首条启动消息

## 附带脚本

| 路径 | 用途 |
|---|---|
| `scripts/context_gauge.py` | 读 room_db 备份，量化判定交接时机与膨胀来源 |

脚本支持 `--chat 关键词` 看单对话诊断、`--top N` 调整列出条数、`--zip <路径>` 指定备份。数据来自最新备份，可能滞后于当前对话，脚本会打印快照时间。
